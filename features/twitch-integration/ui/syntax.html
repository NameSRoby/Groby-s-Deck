Writing a command, step by step

Normal words become the bot's reply. A call inside ${...} inserts a value or performs an operation. Start here, then use the tables to look up every symbol.

Remember a value, then use its name

${set roll 18}
${sender} rolled ${roll}.

${set roll 18} remembers 18 under the name roll and prints nothing. ${roll} inserts that remembered value. ${sender} is a supplied variable: the person who sent the command.

Create a temporary name before reading it. Begin with a letter; use letters, digits or underscores, with no spaces. Keep the same capitalization: roll and Roll are different temporary names. Use built-in names exactly as listed in Variables; choose a new name rather than replacing sender or user.

Spaces separate function options. Quotes keep a phrase together: ${set greeting "Welcome back"} remembers those words; ${greeting} displays them. A temporary value lasts for this message or recipe step. Counters and player fields save values across steps, commands and restarts; find them in the Variables table.

Choose what happens: if, else and end

${set roll 18}
${if roll >= 16}
  The roll passes!
${else}
  The roll fails.
${end}
The check is finished.
  1. ${if roll >= 16} asks whether roll is at least 16. Since roll is 18 here, the answer is true.
  2. The text and operations between if and else run when the answer is true. This example prints The roll passes!
  3. ${else} starts the alternative for a false answer. If roll were 9, it would print The roll fails. This part is optional: leave it out when nothing should happen for a false answer.
  4. ${end} closes this choice. Everything after it runs normally, so The check is finished. appears in either case.

Only the chosen block runs: an XP award or counter change in the other block does not happen. Each if needs its own end. A choice inside another choice needs another pair; the language allows up to three nested choices.

Indentation and line breaks make the source easier to read. They do not decide which block runs; if, else and end do. Preview shows the final chat wording and spacing.

Combine or reverse conditions

Use these inside one if condition. Comparisons happen before AND, and AND happens before OR. Parentheses make your intended groups clear. Do not write 1 < roll < 20: write roll > 1 && roll < 20. Every value in a calculation must be valid; AND and OR do not hide an invalid calculation such as division by zero.

Calculate a number

Use ${math expression} to print an answer, or ${set name expression} to remember it without printing. Multiplication, division and remainder happen before addition and subtraction. Operations at the same level run left to right. Parentheses change that order. Use a decimal point (2.5), not a decimal comma (2,5). Division by zero is an error.

Choose, round or limit a number

These functions go inside a calculation, for example ${math min(8, 12)}. Put the inputs inside parentheses and separate them with commas. The order matters: clamp takes the number, the lower limit, then the upper limit. A calculation can be fractional; saved counters and player fields require whole numbers.

Compare words or usernames with same

${if same sender user}
  You targeted yourself!
${else}
  You targeted someone else.
${end}

same asks whether two complete text values match. It ignores capitalization, spaces at the start or end, and a leading @, so @Groby matches groby. It does not look for a word inside a longer sentence. Put literal words in quotes: ${if same ${1} "confirm"} checks whether the first command argument is confirm.

Use == and the other number comparisons for numbers. Use same for text. To reverse a text test, remember it first: ${set isSelf same sender user}, then check ${if isSelf == 0}.

Try both outcomes

${set roll 18}
Need 16 or more. ${sender} rolled ${roll}/20.
${if roll >= 16}
  Success! The shield breaks.
${else}
  Failed! The shield holds.
${end}

With 18, the reply ends with Success! The shield breaks. With 9, it ends with Failed! The shield holds. The buttons load this editable example into the preview. They never send chat or change saved records.

To roll randomly instead, replace the first line with ${set roll random 1 20}. That rolls once; every later ${roll} uses the same result.

A few patterns build a whole command

        
Use ${name} for a value and ${function options} to do something. Spaces separate options; quotes keep a phrase together. Normal text is your chat reply.

        
${set roll random 1 20}
${if roll >= 16}
  ${sender} beats ${user} with a roll of ${roll}!
  ${addstat sender wins 1}
${else}
  ${sender} rolled ${roll}. ${user} wins!
  ${addstat sender losses 1}
${end}

        
set remembers a value for this command. if / else / end chooses which block runs. stat / addstat / setstat reads, adds to or replaces a saved player number. Pick your own names such as roll, difficulty, wins or xp.

D20 arena: edit the whole recipe

        
Every rule is built from the same variable calls shown above. Open a section to change its numbers, saved stats or story, then choose Try edited arena.

        
XP is the arena score. Wins earn XP; defeats deduct XP down to zero. Upsets earn more than expected wins, larger winning margins increase the stakes, and natural 1/20 rolls add a critical bonus and penalty. Self-fights change no records.

        
How the editable XP rules work
          
winnerChance is the winner's chance before rolling. margin is the winning margin, capped at 5. A narrow win has no margin bonus.

          
RuleCalculation

            
Winner gains10 + (100 - winnerChance) * 2 / 5 + margin

            
Loser loses2 + (100 - winnerChance) / 5 + margin / 2

            
Natural 1 or 20Add 5 to the award and 3 to the loss, then round both.

            
Protect zero balanceDeduct no more than the loser's saved XP.

          

          
At difficulty 16, rolling 16 wins 40 XP; rolling 20 wins 49 XP. Defending a roll of 15 wins 20 XP. Odds outweigh the margin bonus, so the same winning roll earns more against a harder opponent. Change these formulas in the award section below. The reply uses the calculated amounts automatically. Every 100 XP grants a level; losing XP can lower it.
